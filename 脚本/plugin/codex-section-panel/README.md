# Codex Section Panel

这是一个独立的 Obsidian 桌面插件，用于替代只能发送笔记链接和行号的桥接方式。

## 行为

- 光标放在 Markdown 标题或章节正文内时，插件会读取当前章节。
- 支持直接读取编辑器当前选区，替代原 `selection-context-bridge` 的 Codex 选区发送能力。
- 章节范围是当前标题到下一个同级或更高级标题之前。
- 代码围栏中的 `#` 标题不会被当作章节边界。
- 顶部输入框只显示问题，不显示章节正文；上下文范围以可移除的标签显示。
- 章节正文只作为当前 turn 的临时输入发送；请求结束后，插件释放待发送范围。
- 回形针预览所需的引用正文只保存在对应的本地“我”消息中，不作为全局选区缓存。
- 问题和 Codex 回答会按对话保存到插件数据中，可在历史列表中切换。
- 用户消息和 Codex 消息使用不同的角色样式显示。
- Codex 最终回答按 Markdown 渲染；带进度说明的结构化编辑结果会提取摘要，避免把协议 JSON 和转义换行直接堆在聊天正文里。
- Codex 回答通过 JSONL 流式输出，生成过程中可以点击“暂停”。
- “新建对话”会保留旧对话，并创建一个独立的本地历史记录。
- “添加当前选区”可以累计多个不同选区；重复添加同一范围不会产生重复标签。
- “读取当前章节”可以累计多个不同章节；重复读取同一范围不会产生重复标签。
- 章节和选区都可以同时作为本次请求的上下文；“清空范围”会移除所有待发送范围。
- 只有点击“读取当前章节”或“添加当前选区”才会附加笔记正文；直接发送普通问题不会因光标位置而自动附加章节。
- 历史列表使用紧凑的标题、时间和对话图标样式；标题优先采用首条引用的章节名。侧栏可以收起，收起状态会保存。
- 历史列表可逐条删除；删除前会确认，删除当前对话后切换到最近更新的剩余对话，删除最后一条会新建空白对话。该操作只删除插件本地历史，不删除 Codex 服务端线程或笔记。
- 章节/选区操作位于面板顶部；输入框在引用范围下方、历史与聊天区域上方，聊天消息区域独立滚动。
- 模型选择器和发送/暂停图标嵌在输入框外框内；输入框可以纵向拖动调整高度。无章节或选区时也可以直接发送普通问题。
- 输入框工具栏中的模型选择器从 Codex app-server 的 `model/list` 动态读取模型版本；也可以在设置中填写默认模型 ID。
- 每个历史对话会保存 Codex thread ID，切换回旧对话后继续使用原有服务端会话。
- 每条“我”和“Codex”消息显示发送时间；悬停消息气泡后可用统一的复制图标复制当前消息。失败的 Codex 消息还提供重试图标，沿用原用户问题、引用和模型并在原气泡中重试，不额外重复一条用户消息。
- 已发送的“我”消息如果带有章节或选区，会显示回形针图标；鼠标悬停图标可预览对应正文，并可点击“复制正文”。
- 引用预览使用窗口浮层，贴近回形针并限制在窗口内；聊天滚动或窗口缩放时会重新定位，按 Escape 可关闭。
- 每条 Codex 消息的阶段动作显示在回答正文之前；阶段容器显示已记录动作的累计耗时。动作可逐项展开/复制，也支持复制全部阶段动作；复制内容包含阶段名称和完整已记录详情。步骤会更新为已完成、失败或已中断，并保存到对应历史消息中。插件不会显示模型未公开的隐藏思维链。
- 所有请求都通过“发送到 Codex”提交；Codex 会自行判断是普通回答还是笔记修改建议。只有解析出格式有效、且引用编号能对应本轮引用范围的结构化修改建议，面板才会在对应 Codex 消息中显示可折叠的差异；摘要保持可见，展开后查看原内容与建议内容。用户确认后才通过 Obsidian API 写回引用笔记，并在成功后标记“已写入”。修改建议可以同时引用并写入多篇笔记；插件会先校验全部范围，写入中途失败时尝试回滚已写入的笔记。

## 安装

将以下文件复制到 Vault 的插件目录：

```text
<Vault>/.obsidian/plugins/codex-section-panel/
├── main.js
├── manifest.json
└── README.md
```

在 Obsidian 中启用 `Codex Section Panel`，然后使用命令面板执行：

```text
打开 Codex Section Panel
```

## 使用

1. 在 Markdown 文件中把光标放在目标章节内。
2. 打开 `Codex Section Panel`。
3. 点击 `读取当前章节`，确认面板显示文件链接和行号范围。
4. 如需组合上下文，可在编辑器中选择文本后点击 `添加当前选区`，重复操作可加入多个选区。
5. 在引用范围下方的输入框填写问题；即使没有选区、章节或 Markdown 光标，也可以直接发送问题。输入框内的工具栏可切换模型。
6. 点击输入框右下角的发送图标，回答会在下方消息区域逐步显示；请求进行时该位置显示暂停图标。
7. 如需停止当前请求，点击暂停图标；已经收到的回答片段会保留在历史中。
8. 如果问题要求修改笔记，仍然点击输入框右下角的发送图标；查看可折叠的原内容/建议内容差异后，点击 `确认写入引用笔记` 才会保存。一次建议可以写入多篇笔记。
9. 悬停任意消息气泡，点击右上角复制图标可复制单条消息；Codex 请求失败时点击重试图标可在原位置重发。在历史列表中点击对话条目可切换会话，点击侧栏箭头可收起/展开；悬浮消息中的回形针后点击 `复制正文` 可单独复制选区或章节内容。

插件只显示公开请求阶段和最终/增量回答，不显示模型的隐藏思维链文本；状态栏会区分推理、资料检索和命令执行，避免把所有等待都误显示成“思考中”。状态栏还会显示总耗时和首段输出耗时；如果 app-server 触发网络重试，还会显示具体错误。请求失败或超时时，插件会先向 Codex 发送 `turn/interrupt`，确认中断请求后再关闭连接，避免遗留仍在运行的 turn；只有明确的线程失效才会重建 thread。首段输出前等待 90 秒、流式输出后连续 180 秒无新内容，或单轮总时长达到 300 秒时，插件会主动结束请求，这只是故障保护，不是正常完成信号。

0.4.4 之前的历史消息未记录阶段详情，无法补出过去的工具输出；更新后的新请求会记录并保存。展示以 Codex 实际发送的公开事件为准，不会补造没有发生的阶段，也不会展示隐藏推理原文。

## 本地验证

运行 `node test.js` 检查上下文、文件修改和阶段事件归并/保存。运行 `node ui-test.js` 使用本地无头 Edge 加载真实插件代码和样式，回放阶段事件，验证浮层定位、缩放、滚动、历史记录及暂停/失败状态；截图保存在 `.verification/`。UI 测试使用模拟的 app-server 事件，不发送模型请求或修改笔记。

左侧“历史对话”列表可以切换旧对话。切换后不会恢复到待发送范围；但已经发送过的引用会保存在对应的“我”消息中，可通过回形针查看和复制。

历史消息会完整保存在面板中。正常续聊只发送本轮问题和稳定的历史引用编号，依靠 Codex thread 保留已发送的引用正文，避免每轮重复提交整段正文。临时断开或请求超时时插件会保留 `threadId`，下一次请求优先恢复原 thread；只有 Codex 明确返回线程不存在、无效或过期时才新建 thread，并把本地问答和去重后的历史引用正文一次性恢复进去。

发送修改请求时，如果当前没有待发送的章节或选区，插件会优先使用当前 app-server 对话已经保留的历史引用；恢复失效的 thread 时，则会从本地历史消息恢复去重后的引用正文。这样可以在离开原章节后继续修改，不必再次添加引用；如果当前对话从未保存过引用，Codex 会只回答问题，不会猜测修改范围。

也可以在 Markdown 编辑器右键菜单中选择 `添加当前选区到 Codex Section Panel`。选区会追加到当前待发送范围中；发送完成后待发送范围会释放。为了支持历史消息中的回形针预览，正文会作为该条“我”消息的引用保存，不会作为全局选区缓存。

面板中只会显示类似下面的范围信息：

```text
[[agent/agent]] (L741:C1-L1054:C1)
```

章节正文不会复制到输入框，但会作为本次请求的临时上下文发送给 Codex。

## Codex app-server

插件通过本机 Codex CLI 启动持久化 app-server：

```text
codex app-server --listen stdio:// `
  -c 'model_provider="chatgpt_http"' `
  -c 'model_providers.chatgpt_http.name="ChatGPT HTTP"' `
  -c 'model_providers.chatgpt_http.base_url="https://chatgpt.com/backend-api/codex"' `
  -c 'model_providers.chatgpt_http.wire_api="responses"' `
  -c 'model_providers.chatgpt_http.requires_openai_auth=true' `
  -c 'model_providers.chatgpt_http.supports_websockets=false'
```

插件通过 JSONL 协议调用 `initialize`、`model/list`、`thread/start`、`thread/resume`、`turn/start` 和 `turn/interrupt`，并实时读取 `item/agentMessage/delta`。为规避当前网络环境下 `wss://chatgpt.com/backend-api/codex/responses` 的 TLS 握手重试，插件让 Codex 使用同一 ChatGPT OAuth 登录的 HTTP Responses 通道；Obsidian 与本机 app-server 之间仍然使用 JSONL 流式通信。

默认路径针对当前电脑：

```text
C:\Users\12032\AppData\Local\OpenAI\Codex\bin\2e5e00daee91c61d\codex.exe
```

如果 Codex CLI 安装位置不同，可在插件设置中修改 `Codex CLI 路径`。

## 网络代理

插件设置中的 `Codex 网络代理` 默认为 `auto`，会快速探测 Clash 常用的 `127.0.0.1:7890`，并只为 Codex app-server 子进程注入 `HTTP_PROXY`、`HTTPS_PROXY` 和 `ALL_PROXY`。也可以填写完整的 `http://host:port` 地址，或输入 `off` 禁用自动代理。

启动 Codex 前，插件会对 `chatgpt.com:443` 做一次短时 HTTPS 隧道探测。代理节点或 TLS 不可用时会立即显示具体错误，不再让请求无提示地等待完整的 90 秒超时。

## 限制

- 需要 Codex CLI 已登录并能正常执行 `codex app-server`。
- 需要 Obsidian 桌面版；不支持移动端。
- 待发送范围在请求结束后会释放；已经发送的章节正文或选区正文会作为对应历史消息的引用保存，不会变成全局选区缓存。
- 文档修改必须先有章节或选区引用；可以修改一篇或多篇笔记中的引用范围。写入前会重新读取并校验所有原文，任一笔记在请求期间发生变化时会拒绝整批写入，避免覆盖新内容。
- Codex app-server 仍保持只读权限，实际写回由用户确认后的 Obsidian API 操作完成，不需要开放 Codex 的全盘访问权限。
- 如果旧历史没有可恢复的 thread，插件会新建 thread，并用本地保存的问答文本和去重后的历史引用正文初始化一次；历史引用超过恢复上下文上限时，较早内容会被省略。
- Codex CLI 的网络重试、模型响应速度和 WebSocket/HTTPS 回退仍由 Codex CLI 控制。
- 如果出现 `request timed out`，插件会先中断当前 turn，再结束本地请求；首段输出前等待 90 秒、开始流式输出后连续 180 秒没有新内容、或单次请求总时长达到 300 秒只是保护边界。优先查看状态栏显示的实际阶段；如果长时间停在资料检索、命令执行或深度推理，原因通常是 Codex 仍在处理该 turn，而不是面板单纯没有刷新。插件不会把超时简单当成线程失效，后续请求会优先恢复原 thread。
- 如果面板已经打开，插件会继续使用最近一个 Markdown 笔记视图作为来源，不要求面板本身成为活动笔记。
